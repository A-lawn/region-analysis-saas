# 区域数据分析平台 v1.0 完整改进清单与执行计划

## 总览

v1.0 定义为「可安全对外试用的商业化 MVP」。基于已完成的代码实施（5 Phase），补齐安全认证、大数据处理、前端可视化三个维度的剩余缺口。总计 **33 项改进**，分 3 个阶段执行，预估 **10-13 个工作日**。

---

## 阶段一：安全认证加固（3 天）

> 优先级：最高。不做无法让真实用户注册使用。

| # | 项目 | 具体做法 | 涉及文件 | 工作量 |
|---|------|---------|---------|--------|
| **1.1** | 注册接口加限流 | `/register` 路由挂 `loginLimiter`，5次/min/IP，防脚本批量注册 | `authController.ts` | 10min |
| **1.2** | 密码复杂度增强 | 最小 8 位，必须同时包含字母和数字，注册时前端+后端双重校验 | `authController.ts`、`LoginView.vue` | 30min |
| **1.3** | 账户失败锁定 | `users` 表加 `failed_attempts INT DEFAULT 0` + `locked_until TIMESTAMPTZ`；登录接口：失败自增计数，≥5 次锁定 15 分钟，成功后重置 | `init.sql`、`authController.ts` | 1h |
| **1.4** | 登录失败常数时间响应 | 用户不存在时执行一次假的 `bcrypt.compare(someFakeHash)`，消除时序攻击面 | `authController.ts` | 30min |
| **1.5** | 密码重置流程 | `POST /api/auth/forgot-password` — 按邮箱查用户 → 生成 reset token（UUID+1h过期）→ 发邮件；`POST /api/auth/reset-password` — 校验 token → 更新密码 → 删除 token。新增 `password_reset_tokens` 表 | `authController.ts`、`init.sql` | 1天 |
| **1.6** | 注册邮件验证码（OTP） | 注册改为三步：提交邮箱+密码 → 创建未激活账户（`status='pending'`）→ 生成 6 位数字 OTP → 发邮件 → `POST /api/auth/verify-email` 校验 OTP → 激活账户。`users` 表加 `status VARCHAR(20)` + `email_otp` + `otp_expires_at` | `authController.ts`、`init.sql` | 1.5天 |
| **1.7** | JWT_SECRET 更换 | 生成随机密钥写入 `.env`，代码中硬编码回退到空字符串（强制配置） | `.env`、`auth.ts` | 5min |
| **1.8** | 前端 auth 路由守卫 | `router/index.ts` 加 `beforeEach`：除 `/login` 外所有路由要求登录，未登录重定向 | `router/index.ts` | 30min |

## 阶段二：大数据处理优化（4-5 天）

> 优先级：高。不改造则 >50MB 文件无法上传、>5000 点前端卡死。

| # | 项目 | 具体做法 | 涉及文件 | 工作量 |
|---|------|---------|---------|--------|
| **2.1** | 大文件分片上传 | 前端：安装 `tus-js-client`，创建 `useChunkedUpload` composable，5MB/片；后端：安装 `tus-node-server`，挂载到 `/api/web/upload/tus`，替换 multer memoryStorage。保留旧 `/upload` 接口兼容小文件（<10MB） | `useChunkedUpload.ts`、`webController.ts` | 1天 |
| **2.2** | 流式 Excel 解析 | `webController.ts` 上传逻辑改为分批读取：用 `XLSX.utils.sheet_to_json` 的 `range` 参数每批 5000 行，逐批校验+入库+释放内存 | `webController.ts` | 0.5天 |
| **2.3** | 入库分批加固 | `projectService.ts` 的 `helpers.insert` 加批次循环（每批最多 2000 行），避免单次 SQL 超长 | `projectService.ts` | 15min |
| **2.4** | 前端点位分页 | `GET /projects/:id/points` 增加 `?page=1&limit=500` 参数，默认 limit=500。返回 `{ points, total, page, totalPages }`。前端 `projectStore.loadProject` 改为分页加载 | `webController.ts`、`projectStore.ts`、`api/index.ts` | 1天 |
| **2.5** | 前端渲染防卡死 | `AMap.MarkerCluster` 插件集成：`useAmap.ts` 补充 `addClusterLayer(points)` 方法，点数 >200 时启用聚合（缩小时自动合并），<200 时显示单个 Marker。`DashboardView.vue` 中加载后调用 | `useAmap.ts`、`DashboardView.vue` | 0.5天 |
| **2.6** | 令牌桶全局限流优化 | `rateLimit.ts` 按账户维度增加第二层限流：登录接口 keyGenerator 改为 `ip + ":" + (email or "")`，既防 IP 池轮换也防同 IP 锁定全公司 | `rateLimit.ts` | 30min |
| **2.7** | Redis 内存限制 | `docker-compose.yml` redis 容器设置 `command: redis-server --maxmemory 256mb --maxmemory-policy allkeys-lru`，防止 OOM | `docker-compose.yml` | 10min |

## 关键假设

- **邮件服务可用：** 阶段一中的邮件验证码和密码重置依赖外部邮件服务（SendGrid/AWS SES/阿里云邮件推送），需提前申请并配置 SMTP 凭证
- **高德 API Key 有效：** POI 采集依赖高德 Web 服务 API，需确保 Key 有足够的 QPS 配额
- **OSRM 路网数据自愿部署：** 路网服务为可选增强，v1.0 无 OSRM 时所有路网计算降级为直线距离，不影响核心功能
- **HTTPS 证书由运维侧处理：** certbot 自动续签脚本不纳入代码仓库，由部署人员按文档手动配置
- **监控面板暂不实施：** Prometheus + Grafana 留到 v1.1，v1.0 仅依赖健康检查端点 + Docker 日志
