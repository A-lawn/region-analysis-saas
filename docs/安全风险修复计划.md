## 🔴 Phase 1: CRITICAL — 立即修复（0.5 天）

### 1.1 修复 SQL 注入漏洞

- **风险**: 用户输入直接拼接进 SQL 语句，可被注入任意 SQL
- **文件**: `backend/src/services/spatialAnalysis.ts:238`
- **当前代码**:
  ```typescript
  `SELECT weights FROM site_optimization_models WHERE industry = ${options.industry}`
  ```
- **修复**: 改为 pg-promise 参数化查询
  ```typescript
  `SELECT weights FROM site_optimization_models WHERE industry = $[industry]`
  ```
- **说明**: `{ industry: options.industry }` 已在第 239 行传入但第 238 行未使用占位符，典型的"传了参数但没用"的遗漏
- **验证**: 选址优化面板中选择行业模型（便利店/餐饮/药店）后正常运行

### 1.2 高德 securityJsCode 移出前端源码

- **风险**: `securityJsCode` 是服务端校验密钥，不应出现在前端打包产物中
- **文件**: `frontend-vue/src/composables/useAmap.ts:4`
- **当前代码**:
  ```typescript
  const MAP_SECRET = 'eeae0749f33e47a7d3365f4739f8f9dc'
  ;(window as any)._AMapSecurityConfig = { securityJsCode: MAP_SECRET }
  ```
- **修复方案**: 高德 JS API 2.0 的 `securityJsCode` 实际上是在前端 script 加载时由 CDN 校验的，属于**公开配置**而非密钥。评估后确认风险较低，可以保留。真正需要保护的是 `AMAP_SERVER_KEY`（服务端 API 调用用），该 Key 仅在 `.env` 和 `config.ts` 中，不暴露给前端。
- **操作**: 不做代码修改，在 `.env.example` 和文档中标注 `AMAP_WEB_KEY` 为公开 Key、`AMAP_SERVER_KEY` 为保密 Key
- **验证**: 确认 Web Key 在高德控制台已配置域名白名单

## 🟡 Phase 3: MEDIUM — 建议 2 周内修复（1 天）

### 3.1 OTP 验证码防暴力破解

- **风险**: 6 位数字验证码 100 万种组合，全局限流 100 req/min/IP 下攻击者每分钟可尝试 ~1000 次
- **文件**: `backend/src/controllers/authController.ts:105`、`backend/src/middleware/rateLimit.ts`
- **修复**:
  1. 在 `rateLimit.ts` 新增 `otpLimiter`（5 次/IP/分钟）
  2. `router.post("/verify-email", otpLimiter, asyncHandler(...))`
  3. 新增 OTP 失败计数器：3 次验证失败后将该 OTP 标记为 expired
- **验证**: 快速连续提交错误 OTP → 第 6 次被限流返回 429；同 OTP 错误 3 次后正确 OTP 也无法使用

### 3.2 登录时清理旧 Refresh Token

- **风险**: 每次登录生成新 token 但旧 token 不删除，用户可累积大量有效 refresh token
- **文件**: `backend/src/controllers/authController.ts:117-119` 和 `155-157`
- **修复**: 在 INSERT 新 refresh token 之前先执行：
  ```typescript
  await db.none("DELETE FROM refresh_tokens WHERE user_id = $[userId]", { userId: user.id });
  ```
- **验证**: 连续登录 3 次后，DB 中 `refresh_tokens` 表只有最后一条记录

### 3.3 密码重置接口限流

- **风险**: `/forgot-password` 和 `/reset-password` 无专用限流，攻击者可枚举邮箱 + 洪水重置邮件 + 爆破重置 token
- **文件**: `backend/src/controllers/authController.ts:163,179`、`backend/src/middleware/rateLimit.ts`
- **修复**:
  1. 在 `rateLimit.ts` 新增 `resetLimiter`（3 次/15 分钟/IP 用于 forgot；5 次/15 分钟/IP 用于 reset）
  2. `router.post("/forgot-password", resetLimiter, asyncHandler(...))`
  3. `router.post("/reset-password", resetLimiter, asyncHandler(...))`
- **验证**: 快速连续请求 `/forgot-password` → 第 4 次被限流

### 3.4 分析接口挂载专用限流

- **风险**: `analysisLimiter` 已定义但未使用，攻击者可重复发起重度分析请求消耗数据库资源
- **文件**: `backend/src/controllers/webController.ts`（4 个分析路由）和 `backend/src/middleware/rateLimit.ts`
- **修复**:
  ```typescript
  // webController.ts 顶部添加 import
  import { analysisLimiter } from "../middleware/rateLimit";
  
  // 4 个分析路由全部挂载
  router.get("/projects/:id/analysis/coverage", authRequired, analysisLimiter, validateCoverageParams, ...)
  router.get("/projects/:id/analysis/heatmap", authRequired, analysisLimiter, validateHeatmapParams, ...)
  router.get("/projects/:id/analysis/clusters", authRequired, analysisLimiter, validateClusterParams, ...)
  router.post("/projects/:id/analysis/site-optimization", authRequired, analysisLimiter, validateSiteOptimizationParams, ...)
  ```
- **验证**: 快速连续点击"运行分析" → 第 11 次被限流
